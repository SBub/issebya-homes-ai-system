## Problem

Some values live outside React. Whether the browser is online. A media query. An open event stream. A store from another library. A component that shows one of these has to subscribe to it, read it, and re-render when it changes.

You can do that by hand with `useEffect` and `useState`. Three things go wrong. The first render shows a guess, because the effect has not run yet. The read and the subscribe happen in separate steps, so a change between them is lost. And two components reading the same store in one render can show different values. React calls that tearing: one screen shows two versions of the same value.

## Mechanism

Call `useSyncExternalStore` with three functions. It returns the store's current value and re-renders the component when that value changes.

`getSnapshot` reads the value. React calls it on every render, and again before commit to check that nothing changed in between. While the store has not changed, every call must return the same value by `Object.is`. A primitive is fine. An object must be the same reference. So a store that holds an object keeps the last snapshot and replaces it whole when something changes. It never mutates it in place.

`subscribe` registers a callback and returns a function that removes it. React calls `subscribe` after the component mounts and calls the returned function on unmount. When the store changes, the store calls the callback. React then calls `getSnapshot`, compares the result with the last one, and re-renders only when it differs. If you pass a different `subscribe` function on a re-render, React unsubscribes and subscribes again. So keep `subscribe` outside the component, or in `useCallback` when it closes over a prop.

`getServerSnapshot` is the value for server rendering and for hydration on the client. Both must produce the same markup, so it returns a fixed value that needs no browser API. After hydration, React switches to `getSnapshot`. If that value differs, the component re-renders once. Without `getServerSnapshot`, rendering the component on the server throws.

The "sync" in the name means React reads the value in render, straight from the store. No render mixes an old and a new value. Two things follow. A store change during a transition is applied as a blocking update. And a render must not suspend on the value the hook returns.

## Pattern

The three files below are a working app. Paste them into a fresh Next project, open `/`, and toggle the network in the browser's devtools.

The store module wraps the browser API in the three functions.

```ts title="app/online-store.ts"
export function subscribe(callback: () => void) {
  window.addEventListener("online", callback);
  window.addEventListener("offline", callback);
  return () => {
    window.removeEventListener("online", callback);
    window.removeEventListener("offline", callback);
  };
}

export function getSnapshot() {
  return navigator.onLine;
}

export function getServerSnapshot() {
  // The server cannot know; the browser corrects it right after hydration
  return true;
}
```

`navigator.onLine` is a boolean, so `getSnapshot` needs no cache. Two reads of the same state are equal by `Object.is`. The server has no `navigator`, so `getServerSnapshot` returns a fixed `true`. The server and the hydrating client render the same markup.

The component calls the hook with the three functions and renders the value.

```tsx title="app/OnlineIndicator.tsx"
"use client";

import { useSyncExternalStore } from "react";
import { getServerSnapshot, getSnapshot, subscribe } from "./online-store";

export function OnlineIndicator() {
  const online = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);

  return <p>{online ? "Online" : "Offline"}</p>;
}
```

There is no effect and no state. React subscribes after mount and reads `navigator.onLine` on every render. When an `online` or `offline` event fires, React re-renders. On unmount, React runs the unsubscribe.

A page mounts the indicator.

```tsx title="app/page.tsx"
import { OnlineIndicator } from "./OnlineIndicator";

export default function Page() {
  return <OnlineIndicator />;
}
```

The page is a Server Component. It prerenders with "Online" in the HTML, from `getServerSnapshot`. A browser that is offline re-renders to "Offline" right after hydration.

### The same shape over a stream

A store can hold an object instead of a boolean, and its source may need to be opened and closed. The three functions stay the same. The store adds two things. It keeps the last snapshot and replaces it only when something changes. Its `subscribe` opens the source for the first listener and closes it when the last one leaves. [Server-Sent Events from a Route Handler](/p/sse-route-handler) has that store in full, `app/progress-store.ts`, with the route it reads from. Its component is the indicator above with an object in place of the boolean.

```tsx title="app/ProgressView.tsx"
"use client";

import { useSyncExternalStore } from "react";
import { getServerSnapshot, getSnapshot, subscribe } from "./progress-store";

export function ProgressView() {
  const { percent, step, status } = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);

  return (
    <p>
      <progress value={percent} max={100} /> {percent}% {step} {status}
    </p>
  );
}
```

Every render destructures one snapshot, so `percent` and `status` always come from the same event.

### Wrong and right

The console says `The result of getSnapshot should be cached to avoid an infinite loop`, then `Maximum update depth exceeded`.

🔴 `getSnapshot` builds a new object on every call. Two calls in one render are not equal by `Object.is`. React sees a change on every read and renders again, without end. This is `getSnapshot` in the stream store.

```ts title="app/progress-store.ts"
export function getSnapshot() {
  return { ...snapshot };
}
```

✅ Return the object the store holds. Replace it in `update` when an event arrives. Two reads between events give the same reference.

```ts title="app/progress-store.ts"
function update(patch: Partial<typeof initial>) {
  snapshot = { ...snapshot, ...patch };
  for (const listener of listeners) listener();
}

export function getSnapshot() {
  return snapshot;
}
```

The stream closes and reopens on every render.

🔴 `subscribe` is created inside the component. Every render passes a new function, so React unsubscribes and subscribes again. A store that closes its source on the last unsubscribe closes and reopens it each time. This is the hook call in `ProgressView`.

```tsx title="app/ProgressView.tsx"
export function ProgressView() {
  const { status } = useSyncExternalStore(
    (callback) => subscribe(callback),
    getSnapshot,
    getServerSnapshot,
  );

  return <p>{status}</p>;
}
```

✅ Pass the module-level function itself. Its identity never changes, so React subscribes once.

```tsx title="app/ProgressView.tsx"
export function ProgressView() {
  const { status } = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot);

  return <p>{status}</p>;
}
```

## Pitfalls

- **`The result of getSnapshot should be cached to avoid an infinite loop`, then `Maximum update depth exceeded`.** `getSnapshot` returns a new object or array on every call. Keep the last snapshot in the store and return it until something changes. See Wrong and right above.
- **The component re-subscribes on every render, or the stream reopens on every render.** `subscribe` is created inside the component. Move it to module level. When it depends on a prop, wrap it in `useCallback`. See Wrong and right above.
- **Hydration mismatch, or `Missing getServerSnapshot, which is required for server-rendered content`.** The component renders on the server without `getServerSnapshot`, or with one that reads a browser API. Return a fixed value that the server and the hydrating client both produce. Let the browser correct it after hydration.
- **The store changed but the screen did not.** The store mutated the snapshot in place and returned the same reference. `Object.is` saw no change. Replace the object instead.
- **The source opens twice in development.** Strict Mode mounts, unmounts and mounts the component again. So `subscribe` runs, its unsubscribe runs, and `subscribe` runs once more. Make the unsubscribe undo everything, including closing a source. Then the second run is clean. Production mounts once.
- **A transition stopped keeping the old screen on.** The store changed during a transition, and React applied that update as blocking. Keep store updates out of transitions, or accept the blocking update.

## When not to use

- State that React owns. A form field, an open menu, a selected tab. Use `useState`.
- A value derived from props or state. Compute it in render. Use `useMemo` when it is expensive.
- Data fetched from a server. A query library such as React Query or SWR, or `use(promise)`, handles loading, errors and caching. A store snapshot has none of that, and a render must not suspend on a store value.
- A store from a library that already ships a hook, such as `useSelector` or `useStore`. That hook calls `useSyncExternalStore` for you.
